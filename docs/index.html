ARQUITETURA

Clean Architecture com 4 camadas.

01

Domínio

Entidades, Value Objects, exceções e regras puras. Sem dependências externas.

02

Aplicação

Casos de uso e ports (interfaces). Depende apenas do domínio.

03

Infraestrutura

Adapters: SQLAlchemy, JWT, bcrypt, SMTP. Implementa os ports.

04

Apresentação

Rotas FastAPI + Schemas Pydantic. Injeção via Depends.

REGRAS DE NEGÓCIO

Invariantes do domínio.

01

Documento do Cliente

CPF ou CNPJ — nunca ambos, nunca nenhum.

02

Placa imutável

Placa é imutável após cadastro. Formato ABC1234 ou Mercosul.

03

OS ativa por veículo

Máximo 1 OS ativa por veículo.

04

Adição de itens

Serviços e peças só em EM_DIAGNOSTICO ou AGUARDANDO_ORCAMENTO.

05

Preço congelado

Preço congelado no momento da adição. Nunca editável depois.

06

Reserva de estoque

Reserva na aprovação do orçamento. Estoque insuficiente → HTTP 422.

CICLO DE VIDA

Máquina de estados da Ordem de Serviço.

De Para Ação / Perfil
RECEBIDA → EM_DIAGNOSTICO iniciar_diagnostico() MECÂNICO
EM_DIAGNOSTICO → AGUARDANDO_ORCAMENTO finalizar_diagnostico() MECÂNICO
AGUARDANDO_ORCAMENTO → AGUARDANDO_APROVACAO gerar_orcamento() ADMIN
AGUARDANDO_APROVACAO → EM_EXECUCAO aprovar_orcamento() Público
AGUARDANDO_APROVACAO → CANCELADA recusar_orcamento() Público
EM_EXECUCAO → SERVICOS_CONCLUIDOS executar_servico() MECÂNICO (auto)
SERVICOS_CONCLUIDOS → FINALIZADA finalizar_os() ADMIN
FINALIZADA → ENTREGUE entregar_veiculo() ADMIN
